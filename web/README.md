# Tacit web app

Vite, React 18, strict TypeScript, Tailwind 4, framer-motion, react-three-fiber (r3f 8, drei 9,
three 0.172), zustand, react-router 6, TanStack Query 5, recharts, lucide. Node 24, npm.

## Run

```bash
npm install
npm run dev          # http://127.0.0.1:5710, proxies /api /ws /media /sim to the backend on :8710
npm run dev:mock     # same, but every request is answered by the in-app fake backend
npm run build        # web/dist, which the backend serves at /
npm run typecheck && npm run lint
```

`TACIT_BACKEND=http://host:port npm run dev` points the proxy at another backend.

## Mock mode

`VITE_TACIT_MOCK=1` is a build-time switch (`src/lib/api/client.ts`). Vite removes every
`if (MOCK)` branch and the dynamic imports behind them from a normal build, so the shipped app
only talks to the real backend (check: `grep -c mockFetch dist/assets/*.js` is 0). The real
build also strips `public/mock/` (the mock media).

The fake backend in `src/lib/mock/` answers every route and socket in `docs/API.md` with the
same shapes. A procedural workbench (`mock/scene.ts`) is the single world model behind the mock
video, tracks and twin, so overlays line up. `node tools/render-mock-media.mjs` re-renders the
mock videos, keyframes and thumbnails into `public/mock/`.

## Tests (Playwright, Chromium)

```bash
npx playwright test --project=smoke          # mock backend (starts a mock dev server on :5719)
npx playwright test --project=screenshots    # full-page screenshots into .orchestration/evidence/web/mock/
TACIT_E2E_BASE=http://127.0.0.1:8710 npx playwright test --project=smoke   # the real stack
```

- `e2e/fixtures.ts`: `test` fails on any console error; `REAL`; `openReadySkill`;
  `writableSkillId` (a "QA " test skill on the real stack); `studioUrl` (names real-stack
  captures "QA e2e …" up front so the backend hides them from demo lists).
- The live-camera path uses Chromium's fake devices fed from `e2e/.media/` (generated by
  `e2e/global-setup.ts` from the mock clip with ffmpeg).
- Never write into demo data from a test: on the real stack only touch "QA " skills.

## Where things are

- `src/styles/index.css`: design tokens (colour, type, radius, shadows, motion) and base styles.
- `src/components/ui/`: primitives (Button, Badge, Panel, Spotlight, Tabs, Segmented, Stat, Meter,
  ScoreRing, Sparkline, Ticker, Timeline, Stepper, Toast, Dialog, form controls, ServedByList,
  BackendBadge, ChipTag, VerifiedBadge).
- `src/components/layout/`: top bar (persona switcher sends `X-Tacit-User`), guided tour, page shell.
- `src/lib/api/`: types from `docs/API.md`, fetch client, typed sockets, TanStack Query hooks
  (`useJob` follows `WS /ws/jobs` with a polling fallback), and `normalize.ts`. The backend fills
  skills in stage by stage and some payloads differ from the contract text (verification
  `reproj_rel`, QA rows with `step_index`, audit `run_t` as `[start, end]`); normalise there,
  not in pages.
- `src/lib/featured.ts`: the skill and listing the tour and landing links point at (live ids).
- `src/lib/playback.ts`: one clock for a skill's video, overlays and 3D twin.
- `src/lib/media.ts`: camera frames, microphone with voice-activity cut-off, 16 kHz WAV, captions.
- `src/components/overlay/`: hand skeletons, gaze ray and part boxes drawn over video.
- `src/components/skill/`: SkillPlayer, TwinViewer (reusable 3D twin + `CloudViewer`),
  `twinView.ts` (camera framing from `twin.camera`), and the skill tabs.
- `src/components/studio/`: live capture (`useCapture`), latency HUD, coach panel.
- `src/three/`: Franka kinematics and procedural arm, ghost hands, point cloud, landing hero.
- `src/pages/`: one file per route; `pages/landing/` holds the landing sections.

Design sources (MotionSites, 21st.dev) fetched by the lead are in `docs/design/`; the landing hero
(framed plane with hotspots), the Watch → Earn beam pipeline, the liquid-glass CTA and the
Spotlight card are adapted from them. Background videos live in `public/bg/` (not `/media`,
which the backend owns).
